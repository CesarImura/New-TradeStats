# TradeHub code: parity, hygiene and validation

Repo CesarImura/New-TradeStats, branch `mac-admin-v2`, worktree `~/Projetos/TradeHub/_worktrees/admin-v2` (serves localhost:3000 and is the only deploy source). Talk in Portuguese, UI in English. Next 16: read `AGENTS.md` and `node_modules/next/dist/docs` before using an API you are unsure of. Rules about components and past mistakes: `docs/components.md` (read before editing a component).

## 1. Before changing anything
1. `git status --short` and `git diff --stat`: changes you didn't make are someone else's. Never overwrite, reformat, stash, reset or rebase them. Ask the coordinator whether another thread is active.
2. Find every consumer: `rg` for the export, the file path and the string it renders. `components/admin/ui`, `components/ui`, `components/widgets`, `lib/theme` and `lib/prototype-store.ts` are shared by Admin, Editor and student side.
3. Small and clear task: go. Shared code or ambiguous: short plan first (what changes, files, how you will check).

## 2. Where things live (don't move them)
| Kind | Place |
|---|---|
| Admin and Editor kit (Figma `Admin / *`) | `src/components/admin/ui/` + barrel `index.ts`. A new reusable Admin or Editor component goes here |
| Admin page parts (PageHeader with video, Page, NativeSelect, SettingRow) | `src/components/admin/kit.tsx` (named "kit" for history: it is page parts, not the kit) |
| Form and list helpers with no look of their own | `src/components/kit/` (select-field, control-label, drop-line) |
| shadcn primitives (base-nova) | `src/components/ui/`. Our own files there (`animated-accordion`, `ping-dot`, `trap-tab`, the custom `select`) must never be overwritten |
| Student widgets | `src/components/widgets/` (see `tradehub-widgets`); student pages `src/components/student/` |
| Icons | `src/components/icons.tsx` (Carbon only; there is no lucide-react) |
| Admin tokens | `src/app/admin-tokens.css` (generated from Figma, Tailwind names `bg-a-*`, `text-a-*`, `rounded-a-*`, `t-*`) |
| Maps | `docs/maps/` (components, screens, tokens, CHANGELOG), generated by `scripts/maps/*.mjs` |

shadcn CLI: `npx shadcn add` only with `--dry-run --diff` first; its components import lucide icons (components.json says "lucide" and the CLI has no Carbon option): replace them with `@/components/icons` before saving.

## 3. Figma × code parity
- Figma is the visual reference, code the behaviour reference. Measure both before changing: Figma (get_design_context, get_metadata, full-scale screenshot) and the DOM at 1920 × 1080 (getBoundingClientRect).
- Classify a difference: intentional and documented (keep, e.g. disabled primary button), implementation detail with no visible effect (keep), real parity error (fix). Code defects never go into Figma; Figma limitations never go into code.
- Ignore Figma noise: substitute fonts make text 4–8% wider; the logo ~6%.
- Component mapping lives in `docs/maps/components.md` (status confirmado / provável / pendente). When you connect a Figma component to code, cite its exact Figma name in the file's doc comment ("Admin / Page header"); the map then marks it confirmed.
- Screen names cited in code (comments, `src/components/prototype/flows.ts` `figma:`) follow the Figma name exactly; when Figma renames, update them (see `docs/maps/CHANGELOG.md`).

## 4. Removing, renaming, dependencies
- Remove a file or export only when `rg` finds no consumer in `src/` and `scripts/`, including strings, registries and dynamic imports, and tsc + build pass after. Graph scripts (`~/Projetos/TradeHub/docs/reorganizacao/scripts/graph.mjs`, `exports.mjs`) are heuristics, not proof. Parked screens stay (Journal, AI assistant: `admin/journal/*`, `admin/ai/ai-admin.tsx`), and so does `components/ui/table.tsx`.
- Never rename folders with many importers just for a name. Keep a copy of removed binary files outside the repo (backups/).
- `shadcn` stays in dependencies (`globals.css` imports `shadcn/tailwind.css`). Lockfile edits: only deletions you can explain; `npm ls --package-lock-only` before and after.
- Tokens: never change a value for taste; replacing a hard-coded value with a token must render identically. Check `docs/maps/tokens.md` before deleting one.

## 5. Validation (run what applies, report what you didn't)
1. `npx tsc --noEmit -p .`, `npx eslint <changed files>` (0 errors; scripts/ has old warnings).
2. Build only in an isolated copy: rsync to the scratchpad without node_modules/.next/.git, `cp -cR node_modules`, `npx next build` (the first build can fail with SecurityFatalError and pass on the retry). Never `next build` or a second `next dev` in the shared folder.
3. Visual: `node scripts/visual-diff.mjs capture <before>` before the change and `capture <after>` + `compare` after (22 routes × 390/768/1440; noise floor ≤ 4 px). Only intended changes may differ.
4. Flow tests in `scripts/*.mjs` for the area you touched (forms-rule, tabs-motion, theme-matrix, notifications-*, offers-flow, tours-smoke…).
5. Routes 200 on localhost:3000.

## 6. Server, git and deploy
- localhost:3000 = one `next dev` from `_worktrees/admin-v2` (`scripts/dev-server.sh status|start|restart`). Don't start a second one; if 3000 is down and no TradeHub process exists, start it once with the script.
- Commit, push, PR and deploy only when Gustavo asks; the auto-mode classifier may block commits and pushes even then: give him the exact command. Deploy only with `scripts/deploy-admin.sh` (Gustavo runs it).
- Don't edit the same file as another thread; ask the coordinator.
